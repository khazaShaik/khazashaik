## About

I design and lead the delivery of enterprise systems, and I care most about the unglamorous parts: clear boundaries between services, failure modes thought through before launch, and code a teammate can pick up six months later.

My current platform sits between testers and a complex SAP-backed supply chain. It turns a plain-language request into generated test data, then executes deterministically against SAP, APIs and databases, so a full end-to-end journey no longer needs specialist knowledge to run.

## How I Work

- Write the design down first; a one-page document with the trade-offs spelled out saves weeks of rework.
- Prefer boring, observable solutions over clever ones, and make the failure path as explicit as the happy path.
- Review code as a teaching tool, not a gate, and leave the reasoning behind every comment.
- Ship in thin vertical slices so the team learns from real usage instead of guesses.
